# Rust ADR-001 — Rust V2 Migration Strategy

Status: Accepted for Validation

## Decision

- Rust V2: VALIDATION
- Framework candidate: egui / eframe
- Full rewrite: NOT APPROVED
- Python V1: SUPPORTED REFERENCE IMPLEMENTATION
- Four gates: Golden Baseline → Rust Core → egui Pixel Slice → 3-OS Gate.
- Each gate requires reviewable evidence; the final decision is Go / Adjust / Stop.
- Slint is a fallback only after an explicit egui gate failure and a new decision.
  No parallel GPUI, Slint, Tauri or Flutter implementation is approved.

This is ADR-001 in the **Rust namespace**. It does not replace governance
ADR-001 in [DECISIONS](../DECISIONS.md). The approved decision is indexed there
as ADR-005. The user approved validation, not a full migration or release.

## Boundaries

Keep logical Core / Project / Device / App / Desktop / CLI boundaries.
Do not create six crates in advance. When Phase 0 is reviewed, start with
`mono_core`, a thin `mono_cli`, and a minimal `mono_desktop` validation shell.
Core contains deterministic domain logic, not filesystem or OS transport
implementations. Project domain models remain separate from persistence,
even if they initially share one crate. Split crates only when needed.

DeviceSession → DeviceProtocol → DeviceTransport is the logical boundary.
Do not invent a protocol or build physical backends during the current phase.
Use a mock only when a concrete validation scenario needs it. No Tokio.

Compare semantic input and output first: bitmap pixels, encoded bytes, glyph
metrics, project semantics, export semantics and, once specified, protocol frames.
SHA-256 supplements byte equality for deterministic artifacts.
Never erase semantic differences through broad timestamp/path/whitespace removal.

## Isolation

Rust development uses a separate worktree on branch `rust`. The original
Python worktree retains its existing user changes. They must not enter Rust
commits. Git state is queried live; the initial base is historical evidence
in [PHASE-0](PHASE-0.md), not a permanent synchronization claim.

## Consequences

Python remains usable while validation proceeds. No complete UI redesign,
Font Studio migration, device manager, Serial/HID suite, updater or cloud work.
First prove bytes, then interaction, then supported platforms. A failed gate
can stop the migration without replacing V1.

Execution and exit criteria: [Validation Plan](VALIDATION_PLAN.md).
